# 운영 데이터 입력 계약 v1

운영 수집기는 UTF-8 JSON 파일을 만들고 `SERVICE_DATA_FILE`로 그 경로를 지정합니다. 앱은 조회할 때마다 파일을 다시 읽습니다. 파일은 완성된 임시 파일을 원자적으로 교체하는 방식으로 갱신하세요. 형식이 깨지면 이전 개방 결과를 재사용하지 않습니다. 최대 크기는 2MiB, 존은 1,000개입니다.

원자료는 공개 디렉터리와 빌드 출력 밖에 보관합니다. 이 파일은 서버 내부 입력이며 시민 브라우저가 직접 갱신할 수 있는 API가 아닙니다. 운영자는 아래 관리자 등록 API 또는 `/service`의 **존 등록** 탭으로만 갱신합니다.

## 연결 전 빈 파일 예시

```json
{
  "version": 1,
  "sourceName": "실제 운영 데이터 수집기 이름",
  "publishedAt": "2026-11-19T19:00:00+09:00",
  "profile": null,
  "zones": []
}
```

파일 이름이나 이 예제를 실행 기본값으로 자동 선택하지 않습니다. 예시를 실제 지역의 자료로 위장하지 마세요.

## 최상위 필드

| 필드 | 형식·의미 |
| --- | --- |
| `version` | 숫자 `1` |
| `sourceName` | 자료 제공자 이름, 1~150자 |
| `publishedAt` | 수집기가 이 파일을 발행한 시각. 오프셋 또는 Z가 있는 ISO 시각, 미래 금지 |
| `profile` | 적용 기준 객체 또는 null. `name`, HTTP(S) `source`, `unit: "명/분/m"`, 증가하는 양수 경계 5개의 `bounds`, `approvedForService` |
| `zones` | 아래 형식의 존 배열. ID는 중복되지 않아야 함 |

`profile.bounds`는 A/B/C/D/E의 포함 상한이며 이를 넘으면 F입니다. 기존 연구용 수치를 실제 운영에 적용할 수 있다고 자동 승인하지 않습니다. 적용 자료를 검토한 운영 주체만 `approvedForService: true`로 발행해야 합니다.

## 주차존 필드

| 필드 | 형식·의미 |
| --- | --- |
| `id`, `name`, `address` | 각각 1~64자, 1~100자, 1~200자 |
| `point` | `[위도, 경도]`. 유한하고 지리 범위 안인 값 |
| `boundary` | 같은 좌표 순서의 닫힌 다각형. 마지막 점은 첫 점과 같음. 4~200점, 0 면적 금지 |
| `parkingAuthorized` | 실제 공간 사용 권한이 확인된 경우에만 true |
| `vehicleTypes` | `scooter`, `ebike` 중 허용 기기 종류 |
| `capacityAppliesToAllTypes` | 두 종류를 함께 허용할 때 공통 정원이 모두에 유효하도록 측정·확인됐으면 true. 미확인 혼합 존은 판정 보류 |
| `layouts` | 1~100개의 측정 배치. 각 항목에 `capacity`(1~1,000 정수), `effectiveWidthM`(주차 후 남는 양수 유효폭), 선택적으로 해당 배치의 `boundary` |
| `windows` | `start`, `end`가 HH:mm인 한국 시간 운영 구간 배열. 선택적 `days`는 일요일 0~토요일 6. 자정 통과 허용. 빈 배열은 시간표상 상시 운영 |
| `preClose` | 선택적 `{ "minutes": 30, "capacity": 2 }` 형태의 예고 정책. 값은 현장 정책에 맞게 지정. 예시를 공통 운영 정책으로 사용하지 않음 |
| `observation` | 실제 15분 관측의 `pedestrianCount15Min`, `observedAt`, `validUntil`, `source` |
| `inventory` | 확인된 주차 수 `parked`, 예약 수 `reserved`(0 이상 정수), `observedAt`, `validUntil` |

모든 시각에는 오프셋 또는 Z가 있어야 합니다. 관측은 미래일 수 없고, 만료와 동시에 신규 가능 안내가 보류됩니다. 10분 자료나 역 승하차 추정을 실제 15분 보도 실측처럼 넣지 마세요. 다른 집계 간격·대리지표를 연결하려면 그 의미와 모델 적용성을 먼저 검증해야 합니다.

기기 종류가 섞인 공간의 공통 정원은 보수적인 혼합 배치를 뜻합니다. 자전거를 킥보드 한 대와 같은 공간으로 환산하거나 차량별 재고를 임의 합산해선 안 됩니다.

## 공개 결과

`GET /api/service/state`는 공개 이름·위치·경계·기기 종류·판정·잔여 대수·관측 시각만 골라 반환합니다. 원자료의 추가 필드, 인증 토큰, 참가자 정보는 전달하지 않습니다. 그런 비밀 필드는 애초에 원자료에 넣지 않는 것이 좋습니다.

축소를 유발한 등급 `triggerLos`와 선택한 배치의 `flow`/`los`를 구분합니다. `nextChange`는 시간표상 개방·조절·폐쇄의 다음 시각이며 미래의 보행 안전이나 실제 개방을 보장하지 않습니다. `validUntil`과 전체 `expiresAt`는 관측·재고 및 다음 시간표 전환 중 가장 빠른 시각입니다.

이 계약에는 실제 기기 제어·회원 정보·이동 완료 권한이 없습니다. 관련 API 문서와 인증 방식이 준비된 뒤 별도 경계에서 연결합니다.

## 운영자 존 등록

서버 환경변수 `SERVICE_DATA_FILE`과 32자 이상의 무작위 `ADMIN_TOKEN`을 설정하면 `/api/admin`이 열립니다. 둘 중 하나라도 없으면 503으로 닫혀 있습니다. 요청은 `Authorization: Bearer <토큰>` 헤더로 인증합니다. `/service`의 **존 등록** 탭은 토큰을 브라우저 탭 메모리에만 두고 저장하거나 URL에 넣지 않습니다. 모바일 화면에는 이 탭이 없습니다.

| 요청 | 동작 |
| --- | --- |
| `GET /api/admin/feed` | 현재 운영 파일. 파일이 없으면 빈 피드 |
| `PUT /api/admin/zones/:id` | 위 형식의 존 하나를 추가 또는 교체 |
| `DELETE /api/admin/zones/:id` | 존 삭제 |
| `PUT /api/admin/profile` | `{ "approvedForService": true }` 또는 `false`로 `server/engine.mjs`의 참고 LOS 기준 승인 여부 지정 |

모든 쓰기는 `publishedAt`을 서버 시각으로 바꾸고 공개 판정과 같은 `evaluateServiceFeed` 검증을 통과해야 저장합니다. 임시 파일을 쓴 뒤 교체하므로 실패하면 기존 파일이 그대로 남습니다. 기존 파일이 깨져 있으면 덮어쓰지 않고 400을 반환합니다. 한 서버 프로세스 안에서는 쓰기가 겹치지 않지만, 여러 프로세스가 같은 파일에 쓰는 구성은 지원하지 않습니다.

존 등록 탭은 견인 후보 탐색지에서 이름·주소·대표점을 가져올 수 있습니다. 경계·배치별 유효폭·15분 보행량·주차 현황은 현장에서 확인한 값을 입력하며, 관측 시각은 한국 시각입니다. 보행량과 주차 현황은 입력한 유효 시간이 지나면 판정이 보류되므로 운영 중에는 주기적으로 다시 저장해야 합니다. 운영시간의 요일 지정은 이 화면에서 지원하지 않으며 API로 `days`를 넣을 수 있습니다.
