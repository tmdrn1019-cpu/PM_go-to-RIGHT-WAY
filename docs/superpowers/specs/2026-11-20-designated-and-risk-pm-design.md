# 지정 주차구역 전체·견인 위험 합성 PM 표시 (짧은 설계)

## 의도
`/service` 서울 지도에 동적 존이 20곳뿐이라 비어 보인다(사용자, 2026-11-20). 그래서 지도에 다음 두 가지를 더 보여 준다.
1. **서울시 지정 PM 주차구역 전체**(좌표가 확인된 251곳)
2. **실제 견인 다발 주소 근처에 있어 견인 위험이 있는 PM**

서울은 TAGO가 PM 위치를 제공하지 않는다. 그래서 PM은 **합성 시연 자료**로 만든다(사용자 선택).

## 목표 / 비목표 / 반목표
- 목표: 서울 지도에 지정 구역 층과 합성 PM 층을 더한다. 견인 위험 PM은 지도와 텍스트 목록에서 모두 확인할 수 있게 한다.
- 비목표: 합성 PM으로 이동 미션을 만들지 않는다(모바일 시연과 별개). 동적 존 20곳의 선정 규칙도 바꾸지 않는다.
- 반목표: 합성 PM을 실제 기기처럼 보이게 하지 않는다. 지정 구역에 운영 상태(개방·축소·폐쇄)가 있는 것처럼 표시하지 않는다. 위험 반경을 법적 반납금지 경계로 표현하지 않는다.

## 접근 방식
- A. 기존 `/api/demo/state` 재사용: 기기가 관악구 4곳에만 몰려 서울 지도 문제를 풀지 못한다.
- **B. 실제 서울 견인 다발 주소 주변에 합성 PM 배치 (선택):** 서울 지도·실제 견인 자료와 맞는다. 모바일 미션과는 연결되지 않는다.

## 설계
- **자료 (`npm run build:zones`)**
  - `data/public-zones.json`을 `version: 5`로 올린다.
  - `designated`를 추가한다: 좌표가 정확 일치한 지정 구역 전체(`id`, `name`, `address`, `district`, `point`).
  - `towingHotspots`를 추가한다: 좌표가 확인된 서울 견인 상위 주소(`address`, `district`, `count`, `point`).
  - 이유: `data/towing-areas.json`은 관악구뿐이다. 서울 전체 견인 좌표는 이 빌드에만 있다.
- **합성 PM (서버 순수 함수)**
  - 견인 상위 주소 50곳 주변에 기기를 흩어 놓는다. 주소당 대수는 견인 건수 비례로 1~6대다.
  - 기기는 대표점에서 0~80m 안에 둔다. 지정 구역 일부에도 정상 주차 기기를 둔다.
  - 같은 입력이면 같은 배치가 나오도록 시드 고정 난수를 쓴다.
  - 견인 주소 대표점에서 **30m 안**이면 `risk: { address, distanceM }`를 붙인다. 30m는 시연 견인 구역 반경을 그대로 쓴 가정이다.
- **API**
  - `GET /api/zones`에 `designated`를 더한다.
  - 새 `GET /api/zones/synthetic-pm`은 `{ synthetic: true, riskRadiusM, period, vehicles }`를 돌려준다. 원본 견인 행은 보내지 않는다.
- **화면 (`/service`)**
  - 지정 구역: 동적 존과 다른 모양(작은 회색 사각 표식)으로 그린다. 툴팁에 "서울시 지정 구역 · 운영 상태 없음"을 적는다. 동적 존으로 쓰인 구역은 중복으로 그리지 않는다.
  - 합성 PM: 일반 기기는 작은 점, 위험 기기는 오류색에 굵은 테두리와 "견인 위험" 툴팁으로 표시해 색만으로 구분하지 않는다.
  - 메뉴에 "견인 위험 PM" 항목을 추가한다. 위험 기기 목록(가까운 견인 주소·거리)과 "합성 시연 자료 · 실제 기기 아님 · 반경 30m 가정"을 표시한다.
  - 범례에 두 층을 추가한다.
- **문서**
  - `docs/public-zones.md`에 새 필드·합성 규칙·한계를 적는다.
  - `CLAUDE.md`의 `/service` 설명을 갱신한다.
- **검증**
  - 합성 배치 결정성·위험 판정 경계(30m)·버전 검사를 테스트한다.
  - 빌드를 다시 실행하고 브라우저에서 확인한다.

## 빌더 재량
- 표식 크기·색 토큰·목록 정렬(거리순 또는 견인 건수순)은 빌더가 정한다.
- 정확한 PRNG도 빌더가 정한다.
