# 실제 서비스 전환 설계

## 사용자 요구와 목적

사용자는 시연용 콘솔을 목표로 하지 않는다. 다음 세 가지를 하나의 서비스로 제공한다.

1. 첫 화면은 상품 소개 웹 페이지이며, 중간의 버튼으로 서비스를 시작할 수 있다.
2. 웹 서비스는 네이버 지도처럼 지도가 화면 대부분을 차지하고, 옆의 여러 버튼·패널로 동적 주차존 형성과 운영 상태를 확인한다.
3. 일반 시민은 모바일에서 주차존을 확인하고 킥보드·전기자전거 이동에 참여한다. 모바일 형태는 **모바일 웹부터 구현**하는 것으로 사용자가 선택했다.

현재 코드는 합성 데이터를 쓰는 로컬 시연 버전이다. 이 문서는 앞으로 구현할 목표를 설명하며, 실제 연동이 완료됐다는 뜻이 아니다.

## 구현 접근과 선택

- **선택한 방향: 하나의 반응형 웹 서비스.** 소개·데스크톱 지도·모바일 시민 화면을 같은 코드와 API로 제공한다. 기존 React/Vite/Astryx/Express와 순수 주차존 엔진을 재사용한다.
- 별도 Android/iOS 앱은 초기 배포·유지 비용과 개발 범위가 늘어난다. 사용자가 모바일 웹을 선택했으므로 이번 구현에 포함하지 않는다.
- 현재의 긴 대시보드 한 페이지는 지도가 보조 요소이고 시민용 기능과 시험 버튼이 섞여 있어 새 요구에 맞지 않는다. 화면 구조를 바꾸고 실서비스 경로에서 시험 제어를 제거한다.

## 화면 구조

| 경로 | 대상과 주요 행동 | 기본 구성 |
| --- | --- | --- |
| `/` | 상품을 이해하고 서비스 시작 | 소개, 문제와 해결 방식, 주차존 운영 과정, 시민/운영사 활용, 페이지 중간의 `지도에서 서비스 시작` 버튼 |
| `/service` | 넓은 지도에서 현재 주차존 탐색 | 화면을 채우는 지도, 왼쪽 탐색 패널, 검색·상태·기기 종류 필터, 레이어 버튼, 선택 존 상세 |
| `/mobile` | 휴대폰에서 주변 주차존과 이동 미션 이용 | 큰 지도, 내 위치 버튼, 터치하기 쉬운 기기 필터, 하단 목록/상세 패널, 미션 수락·이동·정주차 확인 |

`/service`도 좁은 화면에서는 모바일에 맞게 동작해야 한다. 소개 페이지와 시민 화면에서 데스크톱 전용 운영 제어를 노출하지 않는다. 첫 버전에는 설치형 앱이나 별도 관리자 분석 포털을 추가하지 않는다.

## 소개 페이지

- 보행량·보도 유효폭에 맞춰 주차존을 열고 줄이고 닫는 상품임을 먼저 설명한다.
- 상품 설명의 흐름 중간에 실제 지도 서비스로 이동하는 버튼을 배치한다. 상단과 마지막에도 같은 서비스 진입점을 둘 수 있다.
- 시민에게는 가까운 주차존 확인과 도보 이동 참여를, 운영사·자치구에는 공간·시간별 운영을 설명한다.
- 검증하지 않은 견인 절감률, 제휴사 로고, 이용자 수, 고객 후기, 운영 중인 지역을 만들지 않는다.
- 실제 연동 전 기능은 제공 중인 기능과 구분한다. 기술 구현 세부사항이나 테스트 정책을 상품 소개의 중심 내용으로 넣지 않는다.

## 큰 지도와 사이드 패널

- 페이지 본문을 스크롤해야 지도가 나오는 구조를 없애고, 지도 작업 화면을 기본으로 한다. 지도는 이동·확대·축소를 지원한다.
- 왼쪽 버튼은 `주차존`, `이동 미션`, `운영 상태`, `이용 안내`로 패널 내용을 바꾼다. 부가 정보가 지도 전체를 대시보드 표로 밀어내지 않게 한다.
- 주차존 검색, 개방/축소/폐쇄 필터, 킥보드/전기자전거 필터, 지도 범위 안의 목록을 제공한다.
- 존은 등록된 실제 경계가 있으면 면적으로 표시한다. 개방·축소·폐쇄 상태와 선택된 배치를 색상과 텍스트로 함께 표시한다. 지도상의 임의 빈 공간을 허가된 주차존으로 생성하지 않는다.
- 존을 선택하면 현재 상태, 사용 가능한 수용량, 마지막 보행량 관측 시각, 판정 이유, 다음 운영 변경 시각을 확인한다.
- 실시간은 서버의 실제 시간과 수신 데이터로 계산한다. 화면을 자동 갱신하고, 연결 단절·원자료 지연·만료 시 마지막 관측 시각과 상태를 표시한다. 오래된 정보로 반납이나 미션을 새로 확정하지 않는다.
- 미연결 상태에는 운영 중인 존을 합성해 표시하지 않는다. 실제 지역 등록 전에도 지도 탐색과 서비스 안내는 동작한다.

## 모바일 시민 이용 흐름

1. 소개 페이지 또는 모바일 주소에서 서비스에 진입한다.
2. 위치 사용을 선택하면 주변 주차존·이동 대상 기기를 찾는다. 위치 권한을 거절해도 지도 이동과 목록 탐색을 쓸 수 있다.
3. 킥보드/전기자전거를 구분해 목적지, 이동 방식, 거리, 예상 보상, 제한시간을 확인한다. 실제 이동 경로 제공 전 직선을 도보 경로라고 표시하지 않는다.
4. 시민 계정으로 수락할 때 대상 기기의 이동 가능 여부와 목적지 정원을 서버에서 다시 검사하고 예약한다. 운영사 잠금 해제 성공을 확인해야 이동을 시작한다.
5. 이동 중에는 필요한 위치만 갱신하고 경로 이탈·시간 초과를 검사한다. 모바일 웹을 백그라운드로 보냈을 때 위치 수신이 계속된다고 보장하지 않는다. 누락·지연을 실제 이탈로 확정하지 않는다.
6. 도착 후 사진을 제출하면 서버에서 도착 위치, 목적지 정원·운영 상태, 사진 검증 결과를 함께 확인한다. 시민이 사진의 승인/거절 결과를 직접 고르는 시험 기능은 제공하지 않는다.
7. 검증된 완료만 한 번 기록하고 보상을 한 번 지급한다. 목적지 폐쇄·장치 실패·미완료는 대체 목적지 또는 운영사 인계로 처리한다.

시민의 기본 이동 방식은 기존 계획대로 걸어서 끌고 가기다. 전기자전거도 운영사에서 허용한 기기·이동 방식만 대상으로 한다. 킥보드와 전기자전거의 공간 점유량을 같다고 가정하지 않고 실제 배치 기준을 적용한다.

## 실서비스 데이터와 권한 경계

- 실제 운영 데이터 저장소와 기존 `data/demo.sqlite`를 분리한다. 기존 시연 데이터를 실서비스 데이터로 이관하거나 사용자 데이터처럼 노출하지 않는다.
- 공개 조회는 소개·지도·허용된 주차존 정보를 제공한다. 미션 수락·위치·사진·완료 기록은 로그인한 시민 본인의 권한으로 처리한다.
- 존 등록, 정책 변경, 원자료 수집과 차량 상태 변경은 운영자 또는 인증된 운영사 연결만 허용한다. 클라이언트가 보내는 정원·보상·역할·사진 승인값을 신뢰하지 않는다.
- 위치·사진의 목적, 전송 대상, 보관 기간과 삭제 방식은 실제 연동 전에 정한다. 실제 비밀 키는 서버 환경변수로 관리한다.
- 인증·위치·사진·보상 기능을 포함한 서비스는 HTTPS 환경에서 검증한다. 일반 인터넷에 현재 로컬 시연 API를 그대로 공개하지 않는다.
- 실제 계정·보상 정책과 운영사 인증 연결이 준비되지 않으면 이동 시작 기능을 비활성화하고 이유를 설명한다. 임의 잠금 해제 성공, 가짜 완료, 가짜 포인트로 대체하지 않는다.

## 아직 필요한 연동 정보

- **운영사:** 연동 대상 업체, 차량 조회·이동 허용·잠금 해제·기기 경보·완료 확인 API의 이용 권한과 문서. 사용자에게 준비 여부를 질문한 상태다.
- **주차존 원자료:** 허가·제휴된 경계, 기기 종류별 배치와 유효폭, 운영시간표, 실제 수용량·차량 재고.
- **보행 데이터:** 제공처, 적용 지점, 시간 간격, 지연, 사용 가능한 키와 이용 조건. 역 승하차나 넓은 지역의 인구 추정을 개별 보도 실측으로 취급하지 않는다.
- **회원/이동 자격:** 시민 계정과 운영사 사용자 자격의 연결 방식. 실제 이동·보상 자격은 운영사와 정한 검증에 따른다.
- **사진/보상:** 사진 검증 서비스 또는 운영자 검수 방식, 지급 정책과 지급 수단. 외부 전송 전에 처리 방식을 확정한다.
- **지도 제공사:** `네이버 지도처럼`은 우선 큰 지도와 탐색 패널 형태의 요구로 해석한다. 기존 Leaflet/OpenStreetMap을 재사용할 수 있다. 실제 NAVER Maps로 선택하면 등록된 웹 서비스 URL과 Client ID가 필요하다. 이 공급자 선택은 아직 사용자가 확정하지 않았다.

연동 정보가 없어도 소개·지도·모바일 화면과 실제 데이터 입력 경계를 먼저 구현할 수 있다. 실제 기기를 움직이는 부분은 운영사 연결이 준비된 뒤 통합 검증한다.

## 검증과 완료 기준

- 소개 페이지 중간 버튼으로 서비스 지도에 들어가고, 주소 직접 접근·새로고침·뒤로가기가 동작한다.
- 데스크톱에서 지도가 화면 대부분을 차지하며 패널·검색·필터·존 선택이 동작한다. 모바일에서는 지도를 유지하면서 하단 목록과 상세를 이용할 수 있다.
- 실제 시간 갱신, 원자료 만료, 연결 복구, 빈 데이터, 위치 권한 거절을 처리한다. 화면에 시연용 시간 진행·경로 이탈 버튼·사진 판정 선택·초기화 버튼이 없다.
- 기본 주차존 엔진의 경계·시간·단위 테스트를 유지한다. 실서비스 경로에서 시연 데이터와 시연 명령에 접근할 수 없는지 확인한다.
- 미션에는 로그인·본인 권한, 동시 수락과 정원 초과, 장치 실패 복구, 위치 지연, 사진 접근 권한, 중복 완료·보상 방지를 검증한다.
- 모바일 실기기의 위치 갱신과 사진 촬영, 실제 운영사 장치, 배포 환경의 HTTPS는 연동 자료와 기기가 준비된 뒤 별도 확인한다.

## 검토 상태

- 모바일 웹 우선은 사용자가 확인했다.
- 별도 구현자 관점 검토에서 추가로 확인할 중대한 질문은 없었다. 이미 질문한 운영사/API 준비 상태를 반영해 계획을 세울 수 있다.
- 사용자가 이 설계대로 상품 소개·큰 지도·모바일 웹을 먼저 구현하도록 승인했다. 세 화면과 실제 운영 데이터 조회 경계를 구현했으며, 운영사·계정·사진 검증·배포 연결은 후속 범위다.
