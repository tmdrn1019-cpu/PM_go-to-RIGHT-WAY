# 서울시 공공데이터 연결

## 인증키 발급과 서버 설정

1. [서울 열린데이터광장 Open API 안내](https://data.seoul.go.kr/together/guide/useGuide.do)에서 로그인하고 인증키를 신청합니다. 공공데이터포털(data.go.kr)의 키와 다릅니다.
2. 프로젝트의 `.env.example`을 `.env.local`로 복사하고 발급받은 키를 입력합니다. 기존 `.env.local`이 있으면 덮어쓰지 말고 해당 항목을 추가하세요.

```dotenv
SEOUL_OPEN_DATA_KEY=발급받은_본인_인증키
```

3. `npm run dev` 또는 `npm start`를 다시 실행합니다. Node 24의 env-file 로더가 `.env.local`을 읽습니다. 운영 서버에서는 같은 이름의 서버 환경변수를 사용해도 됩니다. 기존 환경변수가 파일보다 우선합니다.
4. `/service` 또는 `/mobile`의 **공공데이터** 탭에서 `수집 연결됨`, 출처와 실제 관측 시각을 확인합니다. `GET /api/public-data`로도 확인할 수 있습니다.

`VITE_` 접두사를 붙이지 마세요. 키는 서버에서만 읽으며 브라우저에 전달하지 않습니다. `.env.local`과 그 밖의 `.env.*`는 Git에서 제외하고 빈 `.env.example`만 추적합니다. 키를 넣어도 서비스 재시작 전에는 현재 프로세스에 반영되지 않습니다.

키가 없으면 외부 API를 호출하지 않고 연결 준비 상태를 반환합니다. 공식 `sample` 키는 1~5행만 허용되므로 실제 연결용 키로 설정하면 수집 오류가 표시됩니다. 앱은 이를 자동 기본값으로 사용하지 않습니다.

각 공식 [API 명세](https://data.seoul.go.kr/dataList/openApiView.do?infId=OA-22832&srvType=A)의 필드만 사용합니다. 주차구역의 좌표·경계·사용 가능 대수, S-DoT 센서 좌표는 이 두 응답에 없습니다. 주소/행정구역 중심점을 주차 경계나 센서 위치로 만들지 않습니다. 센서의 `SENSING_TIME`을 한국 시각으로 해석하며 서버 수집 시각으로 바꾸지 않습니다.

S-DoT를 개별 보도의 정확한 통행량으로 단정하거나 `×1.5`로 15분 실측으로 바꾸지 않습니다. 이번 연결은 공공데이터 참고 조회입니다. 운영 판정용 `SERVICE_DATA_FILE`과 입력 계약은 [service-data.md](service-data.md)를 따르며, 공간 사용 권한·현장 배치/유효폭·실제 15분 관측 또는 검증된 모델·차량 재고를 따로 확인해야 합니다. 공공 목록 수집만으로 기존 존이 개방되거나 미션이 활성화되지 않습니다.

## 수집 범위와 갱신

- 서버 프로세스마다 자료별 메모리 캐시를 하나 유지합니다. 조회가 들어왔을 때 만료 자료만 다시 수집합니다. 별도 스케줄러나 지속 저장은 이번 범위에 없습니다.
- 주차구역은 24시간, S-DoT는 10분 캐시입니다. 동시에 들어온 요청은 진행 중인 수집을 공유합니다. 브라우저는 이 탭이 열리고 보이는 동안 1분마다 조회합니다. 새로고침 버튼은 캐시를 강제 무효화하지 않습니다.
- 각 API의 1~1,000행을 수집합니다. 원본 전체 행 수, 실제 조회 행 수, 일부 조회 여부를 표시합니다. S-DoT의 한 달 전체 이력을 매번 내려받거나 전체 센서를 빠짐없이 수집했다고 주장하지 않습니다. 공식 순서가 바뀔 수도 있으므로 표시 시각과 조회 범위를 확인하세요.
- `수집 연결됨`은 API 요청 성공을 뜻합니다. 관측이 현재와 가깝다는 보장이 아닙니다. 관측 후 30분이 지나면 이 앱의 안내 기준으로 `관측 지연`을 표시합니다. 이 값은 개방 승인 기준이 아닙니다.
- 자료별 요청은 본문을 포함해 5초로 제한하고 응답은 2MiB 이하만 읽습니다. 형식·시각·인원수·결과 코드를 검사합니다. 오류 시 해당 자료는 비우고 마지막 성공 시각만 남깁니다. 1분 동안 재시도를 제한합니다. 다른 API와 운영 상태 조회에는 영향을 주지 않습니다.
- 캐시는 프로세스 단위이므로 여러 인스턴스를 운영하면 각각 호출합니다. 인증키의 실제 허용 호출량·운영 인스턴스 수를 확인한 뒤 공유 수집기로 전환하세요.

## API 전송과 출처

서울시의 현재 명세는 `http://openapi.seoul.go.kr:8088/`을 사용하고 인증키가 URL 경로에 들어갑니다. 서버에서 공식 주소로 직접 호출하며 리다이렉트는 거절합니다. HTTPS 8088은 이번 확인에서 TLS 연결 오류였으며, 이 제공자 구간은 평문 HTTP이므로 서버 환경변수 보관만으로 전송 구간 암호화가 되지는 않습니다. 외부 운영 전 제공처에 HTTPS 지원/공식 보안 접속 방식을 확인하세요. 클라이언트는 이 주소를 직접 호출하지 않으며 원본 URL·원본 오류 메시지·키를 공개 응답에 포함하지 않습니다.

출처는 서울특별시·서울 열린데이터광장입니다. 자료 화면의 공공누리 1유형(출처표시) 조건에 따라 화면에 제공처 링크를 둡니다. 수정·정제된 표시는 서울시의 공식 판단이 아닙니다. 이용 조건과 실제 데이터 제공 범위는 위 공식 페이지를 기준으로 확인하세요.

## 이번 검증의 범위

정규화·캐시·오류·읽기 API는 합성 테스트로 검증합니다. 사용자 인증키 설정 후 실제 주차구역 329곳(관악구 5곳), S-DoT 1,000행에서 센서 108곳(관악구 3곳)의 응답을 확인했습니다. 이 수량은 2026-11-19 조회 당시의 값이며 현재 지원 범위 전체를 보장하지 않습니다. sample은 앱 기본값으로 쓰지 않습니다.

## 견인 이력과 TAGO PM

사용자가 과거 실제 견인 이력으로 분석구역을 설정하도록 선택했다. `npm run sync:towing`은 `aiTbAutoKickboard`의 2025-01-01~2025-12-31 신고 이력을 날짜별로 수집한다. 실제 API의 오프셋 페이지에서 동일 이력이 중복 반환되는 문제를 확인했으므로 일별 1~1,000행 요청을 사용한다. 일일 총 건수와 행 수가 다르거나 1,000건을 넘거나 요청 날짜와 다른 이력이 오면 게시하지 않는다. 최대 동시 요청은 3개이며 시작 간격을 250ms씩 둔다. 요청은 15초 제한과 최대 3회 재시도를 적용한다. 중복 번호·누락된 자치구·오류 시 성공 파일을 교체하지 않는다. 비공개 data/ 원본 JSONL은 진단용으로 남기며 자동 재공개하지 않는다. 관악구의 신고일·조치일·주소·유형이 유효한 건만 같은 주소로 집계하고 제외 건수를 표시한다. 원자료 좌표가 없고 사용자가 주소별 집계부터 선택했으므로 폴리곤이나 현재 법적 금지구역으로 만들지 않는다. 좌표 연결은 [SGIS 주소 변환 안내](sgis-geocoding.md)의 별도 수집 명령으로 제공한다. 완전히 일치한 주소 대표점만 표시하며, 지도상의 원은 건수 표식이다.

TAGO는 [공식 API](https://www.data.go.kr/data/15117668/openapi.do)의 `GetPMProvider`, `GetPMListByProvider`를 HTTPS로 호출한다. 별도 키 `TAGO_SERVICE_KEY`는 `.env.local` 또는 서버 환경변수에 둔다. 서버 재시작 후 `GET /api/pm/vehicles`로 서울 지원 여부를 확인한다. 2026-11-19 실제 응답은 서울 필터 요청에도 세종특별시 ALPACA·GBIKE만 반환했으므로 클라이언트 요청 지역을 신뢰하지 않고 응답 지역을 검사한다. 서울 미지원은 서울의 기기 0대와 구분한다. 서울이 지원 목록에 없으면 PM 위치 화면은 빈 지도 대신 지원 목록의 첫 운영사(현재 세종 ALPACA) 실제 위치를 한 번 자동으로 보여 주고, 그 사실을 화면에 적는다. 세종시는 PM 견인을 시행하지 않고 공개된 중점관리구역 자료도 좌표 없는 이미지 PDF라, 세종 기기를 견인 구역과 대조하지 않는다.

지원 목록에 있는 운영사·도시만 `cityCode`, `provider`로 선택할 수 있다. 각 조회는 5초·2MiB 상한과 1분 캐시를 적용한다. 기기별 원관측 시각은 제공되지 않아 null로 유지한다. 기기 좌표를 수집 시각의 실측으로 단정하지 않는다. 잠금 해제·반납·보상 권한은 없다.

## 주차존 후보 탐색지와 보행량 연결

`GET /api/towing/candidates`는 SGIS 좌표가 확인된 견인 주소를 건수 순으로 훑어, 아직 묶이지 않은 최다 견인 주소를 중심으로 반경 500m(계획서 시범 기준) 안의 주소를 하나의 **후보 탐색지**로 묶는다. 최대 20곳을 견인 건수 합계로 정렬한다. 탐색지는 제휴 공간을 찾을 영역이며 허가 주차존이 아니다. 보도 유효폭·공간 사용 권한·15분 보행량이 공공 자료에 없으므로 모든 탐색지는 `판정 불가`로 반환하고 개방하지 않는다.

`sDoTPeople`에는 센서 좌표가 없다. 운영자가 현장 또는 공식 설치 위치 자료로 확인한 센서 위치를 비공개 `data/sdot-sensors.json`(또는 `SDOT_SENSOR_FILE`)에 `{"version":1,"sensors":[{"id":"센서 SERIAL","point":[위도,경도]}]}` 형식으로 넣으면, 반경 안 가장 가까운 센서의 최신 **10분** 관측을 참고값으로 연결한다. 파일이 없으면 `센서 위치 미확인`과 관악구 관측 센서 수만 표시하며 행정구역 이름으로 위치를 추정하지 않는다. 연결된 값도 15분 실측으로 환산하거나 LOS 판정에 쓰지 않는다.
