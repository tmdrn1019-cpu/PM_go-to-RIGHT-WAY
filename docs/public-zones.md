# 견인 다발 지점 옆 동적 주차존 (공공데이터 기반)

사용자 결정(2026-11-20):
- 현장 실측 없이 공공데이터로 존을 확정한다.
- 지역은 서울 전체로 하고, 목적은 **견인이 많이 일어나는 곳의 해소**와 **혼잡이 많은 곳의 동적 운영**이다.
- 공공데이터로는 서울 어디서도 보행 LOS D 이상이 나오지 않았다. 그래서 이 존들은 LOS 대신 **서울 전체 역·시간 기준선** 규칙(`server/engine.mjs`의 `evaluateRelative`)으로 판정한다. 처음에는 장소별 상대 순위(그 장소 상위 10% 폐쇄)였으나, 한산한 곳도 매일 닫히고 이유에 숫자가 없어 사용자 요청(2026-11-20)으로 바꿨다.
- 이후 사용자 요청에 따라 다음을 해결했다.
  - **주차 허가:** 존을 견인 다발 지점에서 가장 가까운 **서울시 지정 PM 주차구역**으로 옮겼다.
  - **밤 시간 판정 불가, 센서 없는 지점, 같은 센서 공유:** 혼잡도 자료를 S-DoT 센서에서 **가장 가까운 지하철역의 시간대별 승하차**로 바꿨다.

웹 지도(`/service`)는 `GET /api/zones?at=`로 존을 시각별로 판정해 빠른 시계로 보여 준다.

## 만드는 방법

```
npm run build:zones -- data/towing-source-12968.jsonl
```

필요한 것은 서버 환경변수 `SEOUL_OPEN_DATA_KEY`, `SGIS_SERVICE_ID`, `SGIS_SECURITY_KEY`이다. 견인 원본은 `npm run sync:towing`이 남긴 비공개 JSONL이다. 지정 주차구역(`parkingKickboard`), 역 좌표(`subwayStationMaster`), 역별 시간대 승하차(`CardSubwayTime`, 공개된 최근 달)는 실행할 때 서울시 API로 받는다. 좌표는 `data/towing-geocodes.json`과 `data/parking-geocodes.json`에 캐시한다. 결과는 비공개 `data/public-zones.json`(또는 `PUBLIC_ZONES_FILE`, `version: 5`, 존마다 `thresholds` 포함)에 원자적으로 쓴다. v5는 좌표가 확인된 지정 주차구역 전체(`designated`)와 좌표가 확인된 서울 견인 상위 주소(`towingHotspots`)도 담는다. 옛 v4 파일은 읽지 않으므로 다시 빌드한다.

보도 실측 근거를 넣으려면 먼저 `npm run convert:sidewalk`를 실행한다(Python, `openpyxl`·`pyproj` 필요). 이 명령은 비공개 `data/zone-source/spots-2015/spots-2015.xlsx`([조사지점정보 OA-21707](https://data.seoul.go.kr/dataList/OA-21707/F/1/datasetView.do), 2026-11-20 내려받음)와 `data/zone-source/footfall-2015.xlsx`([관찰조사 OA-21705](https://data.seoul.go.kr/dataList/OA-21705/F/1/datasetView.do))를 읽어 `data/sidewalk-2015.json`을 만든다. 두 데이터셋은 열린데이터광장에서 종료 서비스로 표시되어 있다. 파일이 없으면 존은 근거 없이 만들어진다.

## 선정 과정

1. 2025-01-01~12-31 서울 전체 견인 64,734건을 주소별로 묶고, 상위 150개 주소를 SGIS로 정확 일치 변환한다.
2. 견인이 가장 많은 주소부터, 아직 묶이지 않은 주소 중 반경 300m 안을 하나의 견인 다발 지점으로 묶는다.
3. 각 지점에서 **500m 안의 가장 가까운 서울시 지정 PM 주차구역**을 존으로 삼는다. 지정 구역 329곳 중 251곳의 좌표가 정확 일치했다.
4. 그 지점에서 1km 안의 가장 가까운 지하철역 하루 승하차가 서울 역 중앙값 이상이어야 한다("혼잡이 많은 곳").
5. 견인 건수 순으로 정렬하고, 같은 지정 구역은 한 번만 써서 상위 20곳을 고른다.

2026-11-20 결과(승하차 2026-10 기준)는 20곳이다. 역삼역 8번 출구(견인 478건, 다발 지점 97m, 역삼역 176m)부터 독산역 2번 출구 인근(73건)까지이며, 강남·서초 외에 송파·마포·구로·관악·금천이 포함된다.

## 지정 구역 전체와 견인 위험 합성 PM (사용자 요청 2026-11-20)

동적 존이 20곳뿐이라 지도에 두 층을 더한다. 설계는 `docs/superpowers/specs/2026-11-20-designated-and-risk-pm-design.md`를 따른다.

- **지정 구역:** `GET /api/zones`의 `designated`. 동적 존으로 쓰인 구역은 빼고 회색 사각으로 그린다. 운영 상태는 없다(2026-11-20 빌드에서 251곳 중 231곳).
- **합성 PM:** `GET /api/zones/synthetic-pm`(`synthetic: true`). 서울은 TAGO PM 위치를 제공하지 않아 시연용 기기를 만든다(`server/public-zones.mjs`의 `syntheticFleet`, `SYNTHETIC_RULES`). 배치 규칙은 다음과 같다.
  - 견인 상위 50개 주소마다 견인 40건당 1대(1~6대)를 대표점 80m 안에 둔다. 주소 문자열을 시드로 써서 같은 입력이면 같은 배치가 나온다.
  - 지정 구역 3곳마다 1대를 둔다.
- **견인 위험:** 기기가 아무 견인 주소 대표점에서 30m 안에 있으면 견인 위험이다(지정 구역에 세운 기기는 정상 주차라 제외). 30m는 모바일 시연의 견인 구역 반경을 그대로 쓴 **가정**이며 법적 반납금지 경계가 아니다. 2026-11-20 빌드에서 261대 중 59대가 위험이다.
- **화면 규칙:** 합성 PM은 이동 미션과 연결하지 않는다. 실제 TAGO 기기와 섞이지 않게 'PM 위치'·'견인 분석' 화면에서는 숨긴다.

## 남은 한계

- 2026-10 기준으로 하루 폐쇄 시간이 존마다 크게 다르다. 강남역·홍대입구역을 쓰는 3곳은 하루 16시간 폐쇄, 7곳은 폐쇄 없이 축소만 한다(20곳 합계 폐쇄 84시간·축소 85시간). 대역은 승하차가 하루 대부분 기준선을 넘기 때문이며, 5%·15% 비율을 바꾸면 결과가 달라진다.

- 지하철 승하차는 역 주변 보행량의 대리지표이며 그 보도의 실측이 아니다.
- 같은 역을 쓰는 존(예: 삼성역·학동역·봉은사역 인근)은 똑같이 바뀐다.
- 견인 1위 강남구 청담동 77(500건)은 500m 안에 지정 주차구역이 없어 빠졌다.
- 지정 구역의 보도 폭은 현장에서 확인하지 않았다. 보도 실측 근거는 2015년 조사이고, 조사 지점은 존과 47~251m 떨어져 있어 같은 보도라는 보장이 없다. 20곳 중 5곳은 300m 안에 조사 지점이 없다.
- 2026-11-20 확인 결과 15곳 모두 첨두 LOS A(최대 14.3명/분/m)이고, 기기를 세운 뒤 폭으로도 강남역 12번 출구 뒤편 B, 독산역 2번 출구 인근 C(남는 폭 0.8m, 2.0m 미만)가 가장 높다. 서울 전체 1,217개 조사 지점도 98%가 A다. 그래서 지금의 축소·폐쇄는 보행 안전 기준(LOS)이 아니라 역 혼잡 시간 관리 규칙이다. 1시간 평균이라 15분 첨두보다 낮게 나온다.
- 역 승하차를 보도 보행량으로 바꾸는 계수는 만들 수 없었다. 역 400m 안의 S-DoT 센서 64곳과 비교한 결과 R² 0.03, 비율 0.01~2.57이었다.
- 상위 150개 주소만 좌표 변환한다.
- 원자료와 결과 파일은 비공개 `data/`에 두고 커밋하지 않는다.
